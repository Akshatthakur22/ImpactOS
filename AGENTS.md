# Project-wide instructions

## Product design

- Before changing user-facing design, layout, interaction, terminology, or visual components in any project surface, read [`docs/master-design-guide.md`](docs/master-design-guide.md).
- Treat that guide as the shared design reference for the public site, administrator ERP, coach experience, and parent experience, including web and mobile clients.
- Keep shared patterns consistent across surfaces. Prefer the guide's tokens, accessibility rules, responsive behavior, and interaction patterns over one-off page styling.
- Product requirements, safety, privacy, and authorization requirements take precedence. When they require a design exception, keep the exception narrow and explain it in the implementation or review.
